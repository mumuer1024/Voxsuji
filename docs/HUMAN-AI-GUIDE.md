# Voxsuji 人机协作使用指南

> 面向不写代码的用户。你给 AI 一个视频链接和一句需求，AI 用 Voxsuji 把视频变成文字稿，再帮你总结、整理或做笔记。
>
> [English version](HUMAN-AI-GUIDE.en.md)

## 先记住三件事

1. **Voxsuji 只做一件事**：把在线视频变成文字稿（JSON / Markdown / SRT）。
2. **总结、翻译、做笔记是你的 AI 助手的工作**，不是 Voxsuji 的。Voxsuji 不调用任何大模型。
3. **文字稿保存成文件**；AI 只拿到一个很小的摘要和文件路径，所以几小时的视频也不会撑爆 AI 的上下文。

## 一、它能做什么

适合这些场景：

- 看了一个很长的访谈 / 播客 / 网课，想让 AI 用几分钟讲清楚重点；
- 把讲座整理成结构化笔记；
- 需要视频的字幕文件（SRT）；
- 视频没有字幕，需要用语音识别（ASR）把语音转成文字。

它**不**做这些：评论 / 弹幕抓取、视频下载管理、内置 AI 总结。

## 二、它是怎么工作的

```text
你：给 AI 一个视频链接 + 一句需求
 ↓
AI：运行 voxsuji，得到文字稿文件
 ↓
AI：读取文字稿（长文分段读）
 ↓
AI：总结 / 整理 / 回答你的问题
```

Voxsuji 内部：

```text
先找平台字幕 → 有字幕就直接用（免费、快）
             → 没有字幕才：提取音频 → 临时上传对象存储 → 云端 ASR
最后统一输出 JSON / Markdown / SRT
```

## 三、第一次使用：让 AI 帮你装好

### 3.1 你需要准备

- 一台能联网的电脑（Linux / macOS，或 Windows 的 WSL）；
- Python 3.10 或更高版本；
- `ffmpeg`；
- 一个视频链接（YouTube 或其他 yt-dlp 支持的网站）。

### 3.2 把这段话发给你的 AI 助手

```text
帮我安装并检查这个开源项目：https://github.com/mumuer1024/Voxsuji

步骤：
1. git clone 到本地；
2. 安装 ffmpeg；
3. 运行 ./bin/voxsuji doctor，把结果原样告诉我；
4. 如果 doctor 提示缺少配置，只告诉我缺什么，不要自己填任何密钥。
```

说明：AI 执行命令时，你的工具可能会让你点一次"允许"，这是正常的。第一次运行 Voxsuji 会自动创建项目内的虚拟环境，不会弄乱系统里的 Python。

### 3.3 检查结果

让 AI 运行 `./bin/voxsuji doctor`。它会用 JSON 告诉你：依赖是否就绪、默认用哪家 ASR、哪些 provider 和对象存储已经配置好。它不会打印任何密钥。

## 四、日常使用（三种方式）

### 方式一：让 AI 全包（推荐）

```text
用 voxsuji 转写这个视频：<视频链接>

优先用平台字幕；没有字幕再用我配置好的 ASR。
转写完成后，读取生成的 Markdown 文字稿，帮我把主要内容总结成 10 条要点。
```

AI 会：运行命令 → 拿到 JSON 摘要 → 找到文字稿文件 → 分段读取 → 总结。它不需要你把全文复制粘贴给它。

### 方式二：先转写，再让 AI 读

```bash
voxsuji transcript <视频链接>
```

命令结束后会告诉你文件在哪里（通常在 `cache/<平台>/<视频ID>/`）。然后把路径发给 AI：

```text
读取 <路径>/transcript.md，帮我整理成结构化笔记。
```

### 方式三：需要字幕文件

`transcript.srt` 可以直接当字幕用；`transcript.json` 是带时间戳的结构化数据，适合程序处理。

## 五、视频没有字幕：ASR（可选）

默认是"字幕优先"：只有找不到可用字幕时才会调用 ASR。启用 ASR 需要两样东西：

1. **一家云端语音识别服务**：阿里云百炼、火山引擎、腾讯云，任选其一；
2. **一个 S3 兼容的对象存储**：ASR 服务需要通过公开 URL 读取临时音频。

让 AI 带你配置：

```text
帮我配置 Voxsuji 的 ASR，我打算用 <阿里云百炼 / 火山引擎 / 腾讯云>。

请告诉我：
1. 需要设置哪些环境变量（只给变量名，不要打印真实值）；
2. 对象存储需要满足什么条件；
3. 配置完成后运行 doctor 检查。

密钥我自己填到 .env 里。
```

**费用提醒：**

- 有字幕时通常不产生 ASR 费用；
- 走 ASR 按你自己的服务商账户计费；
- `--force-asr` 会跳过免费字幕、强制走 ASR，非必要不要用。

**隐私提醒：** 走 ASR 时，音频会临时上传到你自己的公开可读 bucket，转录完成后自动删除。这期间知道链接的人理论上都能访问到这个临时对象。

## 六、长视频与缓存

- 文字稿在文件里。告诉 AI "文字稿很长就分段读"，它就不会一次性把全文塞进上下文。
- 同一个视频再运行一次，会直接复用缓存（返回 `"cached": true`），不再下载、不再调用 ASR。
- 想重新处理：`--refresh`；想强制重跑 ASR：`--force-asr --refresh`（会产生费用）。

## 七、常见问题

**为什么屏幕上没有全文？**
这是有意设计。stdout 只返回一个紧凑的 JSON 摘要（包含文件路径），避免长文字稿刷屏或撑爆 AI 的上下文。全文在文件里。

**提示缺少配置 / 退出码为 3？**
说明你选的 ASR provider 或对象存储没配好，错误信息会指出缺哪个变量。让 AI 读错误信息即可；不要把密钥发到聊天里。

**视频明明能看，但拿不到内容？**
有些网站对未登录访问有限制。可以准备一个 Netscape 格式的 `cookies.txt`，配置到 `[cookies] file`，并设成 `chmod 600`。不要把它提交到 Git。

**能抓评论和弹幕吗？**
不能。公开版 Voxsuji 明确只做文字稿和字幕，不做评论 / 弹幕。

**Voxsuji 会帮我总结吗？**
不会。它不调用任何 LLM。总结请交给你的 AI 助手，或使用 `prompts/` 目录里的模板。

**数据存在哪里？**
默认在项目目录的 `cache/` 下；可以用 `VOXSUJI_DATA_DIR` 改到别的位置。

**支持本地视频文件吗？**
当前版本只接受在线视频 URL。

**该选哪家 ASR？**
只配你实际使用的一家即可，三家互相独立。不确定就先用默认的阿里云百炼，或者问你的 AI。

## 八、安全与隐私清单

- API Key / Secret 只放 `.env`（`chmod 600`），不要粘贴到聊天、不要提交到 Git。
- `cookies.txt` 同样设成 `chmod 600`，不要提交。
- 对象存储里的临时音频在 ASR 期间是公开可读的，完成后自动删除；不要用它处理敏感内容。
- 你的 AI 工具读取文字稿时，内容会进入它的上下文，注意隐私。

## 九、进阶（可选）：把 Voxsuji 包装成 MCP 工具

如果你的 AI 客户端支持 MCP（Model Context Protocol），可以自己写一个很薄的 MCP server：收到转写请求后，执行 `voxsuji transcript <URL> --json`，把 JSON 摘要和文件路径返回给 AI。

**好处**：AI 调用工具时不用每次申请终端权限，返回的是结构化结果，适合把 Voxsuji 当成"随时可用的工具"。

**说明**：公开版 Voxsuji 不内置 MCP server。这是可选的自行集成方式，不是项目功能；不需要的话完全忽略这一节。

## 十、提示词速查（直接复制）

安装检查：

```text
帮我安装并检查 https://github.com/mumuer1024/Voxsuji，然后运行 doctor 告诉我缺什么。
```

转写并总结：

```text
用 voxsuji 转写 <URL>，优先字幕。完成后读取 Markdown 文字稿，总结成 10 条要点。
```

只转写：

```text
用 voxsuji 转写 <URL>，把生成的文件路径告诉我即可，先不要总结。
```

结构化笔记：

```text
读取 <路径>/transcript.md，按"背景 / 关键观点 / 行动项"整理成笔记。
```

只要字幕：

```text
用 voxsuji 转写 <URL>，把 transcript.srt 的路径给我。
```

失败排查：

```text
voxsuji 报错了：<错误信息>。请根据 doctor 的输出和 .env 配置帮我定位原因，不要打印密钥。
```

长视频分段：

```text
<路径>/transcript.md 很长，请分段读取，先给我整体结构，再逐段总结。
```
